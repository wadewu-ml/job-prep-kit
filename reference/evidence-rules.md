# 信息来源与证据规范

## 首选来源和适用范围

**企业官网、经官网链接确认的官方招聘系统、学校官方就业信息网是最高优先级渠道。** 学校包括本校和其他高校；本校优先用于本校场次与手续，不因外校转载就否定其完整招聘简章。

| 来源 | 能支持什么 | 核验边界 |
|---|---|---|
| 企业官网/官方招聘系统 | 招聘主体、具体 JD、资格、当前开放状态、投递入口 | 从官网或可信官方公告确认外包系统租户，不凭域名外观判断官方 |
| 学校官方就业网 | 当届校招简章、岗位与待遇公告、校园安排、学校手续 | 核发布单位、日期和届次；转载可能过期，实时岗位状态回企业系统查 |
| 企业官方公众号 | 企业公告、补录或场次变动 | 验证账号主体，保存原文定位，不能仅凭转发截图 |
| 本人收到的邮件/短信/系统通知 | 本人的测评、面试、录用、截止 | 核对发件人与岗位；不代表全公司统一政策；敏感链接只在私有证据区保存 |
| HR或团队成员原话 | 当时对该岗位/团队的说明 | 记录对象、时间、问题和原话；口头说明不等同于书面承诺 |
| 社区/第三方招聘平台 | 发现入口、准备核实问题、个人工作体验 | 保留样本和时间，不用于确认官方截止、薪资保证或本人状态 |
| AI回答/搜索摘要 | 检索线索 | 不当作事实来源，必须打开原始页面 |

“官方”也不自动意味着每句话适用于本岗位。核对法人/团队、岗位编号、学历、毕业窗口、地点和生效时间。公告发布日、面试日、核验日分开记录。

## 每条重要事实的最小证据

断言｜来源类型｜原始 URL 或私有文件定位｜必要的原文短摘录｜适用岗位/届次｜事件日期｜核验时间｜已确认/待核/推断/冲突。

私有通知只摘录必要事实，公开材料不保存身份证、联系方式、会议密码、访问令牌。证据字段存在只能证明记录格式齐全，脚本无法替代人工核验真伪。

## 查证顺序

1. 查企业官网的最新招聘/新闻列表与官方系统，读完整 JD；同时查学校官方就业网的当届简章。
2. 无法获取时核入口、届次、页面渲染和链接是否失效；使用允许的浏览器或其他官方镜像。抓取失败不等于没有招聘。
3. 官方材料仍不足时明确缺口，再用第三方发现线索或向招聘方核实。不要无限搜索，记录已查范围和下一步。
4. 来源冲突时并列保存日期、主体和原文，优先针对本岗位且较新的直接证据；未解决前标冲突，不能机械取低值或凭多数票决定。
5. 提交前重新打开目标入口，确认岗位仍可投、志愿上限和顺序。历史记录不当作当前开放状态。

## 岗位决策的三种结果

- **匹配且无已知底线冲突**：核实本届开放和基本资格后可建议申请。
- **信息不足**：薪资、班制、团队或地点未披露，列出待问问题与核实阶段；用户知情授权后可以申请，不能当作默认接受。
- **已确认冲突**：明确违反用户底线或不满足硬资格，说明证据；未经用户改变偏好不进入执行队列。

“专业名称出现在列表”不是全部匹配证据；“岗位叫研发”不证明实际做内部研发；集团不同法人、团队的条件不能相互平移。

## 日期、薪酬与状态

- deadline / 🔒：原文明确的硬截止，必须有来源和时区。只有日期时保留原粒度，不自造具体时刻；需要精确提醒时先核实。
- scheduled / 📅：官方约定的考核/场次，可能调整；不能把它降格成助手建议。
- suggested / 💡：自己安排的跟进或准备时间，不冒充官方截止。
- 待核：无法确认的日期，不生成硬截止提醒。

薪资分别列固定工资、发薪月数、浮动绩效、条件性补贴和一次性奖励。未知月数不换算保证年薪；总包和到手收入不混用。第三方薪资不能单独支持放弃或接受决定。

暂存、上传、预览均不是已投；有可定位官方回执或发送记录才登记提交。面试自我感觉与官方结果分开。新证据更新当前状态，历史事件保留原来源，不抹去冲突。
