# 走一遍求职工作区

全部是合成材料，不属于真实候选人或招聘。演示日程以创建目录时的日期生成，example.invalid 是占位地址。

1. **从材料开始**：打开 records/facts.md，沿链接读课程项目详情。事实、简历短句和面试讲法都在同一份经历中，不需要重复填写另一套资料。
2. **定位岗位**：applications/data.json 的 materials 关联了合成 JD 和面试记录。注意没有真实已发简历，因此保持“历史附件待补”，不拿新稿冒充旧附件。
3. **打开看板**：在工具项目运行 `python scripts/tracker.py render --workspace <本目录>`，双击 applications/dashboard.html。顶部先看面试、测评和录用回复的具体动作；下方分别阅读岗位概况、跟进任务和相关材料。等待反馈的记录留在列表，不产生催办任务。按“待申请 / 历史与不跟进”筛选，或搜索关键词；从顶部事项点进岗位，会定位该记录并清除遮挡它的筛选。示例含六条虚构记录，无真实录用或附件。
4. **看看经验怎样用于建议**：读 interviews/synthetic-practice.md 的合成练习复盘，再读 lessons/project-opening.md 与 interviews/synthetic-001.md。一次反馈如何变成待验证改法、怎样改变本次准备，在文件和看板的“建议依据”中均可追溯。不要把合成反馈当成真实结果。考核实际完成时，再把对应事件 done 改为 true、更新 next_action，并按 workflows/06-复盘与经验复用.md 留下有用发现。重新生成后，完成事件离开近期待办，记录仍保留。
5. **真实使用**：将本目录交给助手即可演练 Skill 的流程。真正开始时另建空白工作区，或沿用自己已有的私人目录，避免把合成数据混进真实投递记录。

材料留在原处也可以，materials 支持绝对文件路径与官方网页。简历制作由助手使用可用的文档工具完成，本演示不宣称生成了可投递的 DOCX/PDF。
