# 岗位筛选：职责、证据和未知条件

先读本人方向、底线、当前已投/放弃记录，避免反复推荐。先核公司全称、别名和招聘项目；集团名称相近不一定是同一申请，换了简称也不一定是新机会。企业官网和学校官方就业信息网优先，按 reference/evidence-rules.md 留证。

## 每个岗位一张判断卡

- 企业法人 / 项目 / 岗位全名与编号 / 地点 / 届次与毕业窗口。
- 本届开放证据、实际申请入口、核验日期；第三方链接只作指路。
- 完整 JD 中 3–5 项关键任务与硬要求：职责在做什么、产出交给谁、实际工作场景。
- 本人每项直接证据 / 相邻经验 / 缺口；不由专业名称或岗位前缀直接判断。
- 薪资、班制、出差驻场、工作地分别标已确认 / 未披露 / 有冲突。
- 结论：优先申请 / 可申请并待核 / 暂缓核实 / 不符合；理由和下一动作。

公司名、行业热度和熟人推荐不能替代职责核实。同叫研发的岗位可能分别做内部开发、生产支持或客户交付；同叫分析的岗位也可能是例行测试或方法开发。向团队问“新人前半年做什么、开发与重复执行各占多少、由谁带教”比只问岗位头衔更具体。

## 申请与接受录用分开

本届开放且资格匹配，没有已知底线冲突时，未知薪资/班制可留到沟通阶段核实，不默认淘汰，也不能默认接受。岗位选择由用户决定；已确认底线冲突需说明，不用高薪或知名度替用户覆盖底线。

有限志愿先核名额、顺序、修改规则、统一招聘项目与子公司是否共用入口。内推模式和官网重复提交规则逐公司确认；剩余名额不是增加投递的授权。

最终输出短名单，列可靠来源和关键缺口，不用来源不明的“上岸概率”打分。保存到 company-info.md；批准的岗位记录进入 applications/data.json。
