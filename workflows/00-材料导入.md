# 从已有材料开始

用户可以只给一份旧简历、一个材料目录或一条 JD。先明确这次要完成的事，读指定材料和已有记录；不要求先填完 PROFILE，也不扫描无关目录。

## 导入

1. 在用户指定的个人工作区处理；没有时用 init_workspace.py 创建。原文件留在原处，通常登记路径即可。
2. 先读与当前任务相关的简历、项目说明或通知。用当前可用的文档工具提取内容；图片或扫描件需查看原页，读不清的数字标待核，不靠猜测补全。
3. 将可复用事实合并进 records/facts.md，沿用已有 ID。个人偏好与网申字段按需补到 PROFILE.md；不同材料有冲突就保留来源和日期，问会影响当前结果的那一项。
4. 直接完成这次要求的简历、岗位分析或面试准备，再说明仍需补的内容。不是仅交付一堆已填模板。

## 经历复用

材料少时，一张 facts.md 就够。某段经历长到难以放进表格时，才建立 `records/experiences/<主题>.md`，在事实行的“来源/详情”中链接它；这张表同时就是索引，不另建一套目录台账。

详情可按下列结构整理，删掉不适用部分：

```markdown
# 项目/经历名称
事实 ID：F001
来源：原文件路径与段落/页码，或本人确认时间

## 事实
对象与问题；本人实际环节；方法；结果与条件；未知或不能推断的部分。

## 可复用表达
简历：简短、与岗位相关的段落。
网申：有字数要求时再扩写。
面试：先让人听懂对象，再讲具体判断与动作。

## 相关反馈
从哪次复盘发现了什么表达问题，下次如何回答；链接原记录。
```

新 JD 到来时先查 facts.md 的主题、角色与结果，再读相关详情和原件。改变顺序、篇幅和措辞，不把相邻经验改成直接经验。复盘得到的新讲法更新到该经历；面试自评和他人建议不能直接变成个人事实。

## 关联到岗位

在 `applications/data.json` 的相应岗位添加可选 `materials`：

```json
"materials": {
  "jd": "applications/role-001/jd.md",
  "resume": "resumes/archive/general-v1.pdf",
  "interview": "interviews/role-001.md"
}
```

路径相对个人工作区，也可以是已有文件的绝对路径或官方网页 URL。缺哪项就省略，不创建假文件。JD 原文/摘录保留官方来源、岗位与核验日期；提交过的 resume 指向实际发送的留存件，不指向以后会被覆盖的 current 文件。状态和日程仍只记一份台账，面试正文里不用再维护一次。
