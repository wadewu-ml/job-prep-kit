# 简历：先有事实，再有表达

## 输入与事实台账

先读 PROFILE.md、records/facts.md、当前母版和目标 JD。新材料按 [材料导入](00-材料导入.md) 合并；从 facts.md 定位后只读相关经历详情。已有原件或本人确认的答案不重复问。缺材料时先做可完成的结构与措辞，只询问阻碍准确性的内容。

每条素材记：做的对象/问题、本人具体环节、方法、结果、来源与时间、允许说法、不能推断什么。区分原文件证实、本人确认、待核和不采用；不能从论文作者顺序推断全部实验归属，也不能将观摩实习改成亲手操作。

日期用已知粒度；成绩/排名按正式记录，不自造换算；接收和发表按当前出版证据分别写；预期获奖不能写已获奖。AI建议和其他人的简历不是本人事实。

## 母版和方向版

1. 先稳定一份可编辑母版，再按确有差异的岗位做少量方向版。方向版改变顺序、篇幅和讲解深度，不改变事实与贡献。
2. 项目先让外行理解“对象是什么、解决什么问题”，再连贯说明方法和结果，个人贡献作为必要补充；避免逐项罗列职责。面向非本领域读者解释必要术语。
3. 结果有数字就保留条件、单位、基准和必要限定；没有可信统计时用具体动作与可核验产出，不补造百分比。
4. 技能写实际能完成的任务，区分会操作、处理过数据、了解原理。相邻经验可解释迁移，但不包装为未做过的工业/商业项目。
5. 一般先尝试简洁的一页，内容需要时可两页；不以缩小到难读的字号强行压页。照片、年龄、成绩等按申请要求与使用者选择，不设置统一个人画像。

初稿可用 resumes/source/master.md。具有文档工具时输出可编辑 DOCX，并另行导出 PDF；工具不可用时交付明确标注的正文稿和排版要求，不谎称已完成渲染验证。

## 反馈处理

把每条意见映射到当前稿：事实修正 / 表达优化 / JD取舍 / 需要补证 / 不采纳。重复意见不证明正确，匿名稿缺失学校/姓名可能是有意处理。外部改稿不覆盖正式版；只采纳有证据且符合用户意图的改动。

## 完成标准

- 逐条核对姓名、教育、日期、数字、职责、论文状态和链接，不把研究方向替代正式网申专业。
- 导出后查看每一整页：裁切、行距、对齐、照片比例、页数、字号、孤行；不能只看文本或截图局部。
- 提取 PDF 文本，检查阅读顺序和内容完整性；DOCX/PDF文字应一致，化学式/数学上下标用原生格式并核查解析。
- 清除批注、修订、隐藏信息，做工具支持的无障碍检查；不要声称通过未运行的检查。
- 保留当前稿和已发附件的对应关系；current 保存当前文件，archive 保留旧版。需要核对文件是否变化时再使用可选的 versions.json 和哈希工具，不把登记检查表当成做简历的前置条件。

只在用户确实要求改稿时更新正式文件。评审、证据池扩展或新职位线索不会自动触发全面重写。
